## Owner-verified behaviour

- The custom Default launcher, applications, source selection and Home return work.
- Native Home and launcher startup were tested after a power disconnect earlier
  in development. This is separate from automatic root acquisition.
- All three app transition choices — None, Fade and Standard — work with Spotify
  and YouTube, and Home remains functional.
- Spotify's Samsung loading dots and bar disappeared with the launch hint below.
- Selecting a sleeping Apple TV on HDMI 1 wakes it, shows its picture, and Home
  returns to the launcher. CEC reported standby `1` before the first wake and on `0`
  afterward; the owner also confirmed the complete source-tile flow after installation.
- A separate transparent foreground video layer prevented the system's idle dots
  during an observed four-minute test, independently of the decorative widget.

The on-TV root helper is installed and works in the current boot. **Automatic root
reacquisition after a cold boot remains unverified on this S95F.** The deferred test
is documented in the [root setup guide](../root-cli.md#user-flow). No claim of
permanent firmware root or verified unattended recovery is made.

## Implementation notes

### Samsung loading overlay

Launch application controls with `__NO_LOADING_LAUNCH` set to `enable` and retain a
normal-launch fallback. This is a firmware-specific, undocumented behaviour. It
suppresses Samsung's launch overlay, not splash screens drawn by applications.
See [createAppsPlatform.ts](../../launcher/src/platform/tizen/createAppsPlatform.ts).
No modified Samsung animation resources are required by the final implementation.

### Application transitions

The root helper applies per-window auxiliary hints:

- `wm.comp.win.effect.enable`
- `wm.comp.win.effect.style`
- `wm.monitor.skip.deskzoom`

The controller tracks window identity, preserves pre-existing hint IDs and values,
handles newly created app windows, verifies readback, and restores its changes when
stopped. See [the controller](../../cli/native/window-transitions/TransitionPolicy.cs).

Do not treat `enlightenment_info -effect 0` as an animation preference: on this
firmware it unloads the effect module. Earlier experiments were followed by Home
failures and restarts; causation was not established. The final code never uses it,
patches the compositor binary, or writes process memory.

### Waking HDMI devices

On this firmware the system D-Bus service `org.tizen.tv.hdmicec`, object
`/org/tizen/tv/hdmicec`, interface `org.tizen.tv.HdmiCec` exposes
`SetDeviceStreamPathByHdmiPort(int32 port)`. Activating port 1 returned `0` and woke
the attached Apple TV with Anynet+ enabled.

[HdmiWake.cs](../../cli/native/hdmi-wake/HdmiWake.cs) accepts only bounded, fresh
requests for ports 1–4 in the launcher's private app directory. It cannot execute
caller-supplied commands. Discovery does not wake devices, and the UI cancels stale
handoffs. This is a downstream use of the TV's existing CEC service, not a new root
exploit. Other HDMI devices and firmware implementations need their own tests.

## Local debloat findings

The owner tested reversible `app_disable` flags for the Samsung analytics, ACR,
iACR, targeted-ad, ePop and ADPlayer applications. YouTube, Home, settings and Sources
continued working in that session. Earlier PISA / advertising-agent runtime masks
were cleared by reboot and are not part of the current launcher implementation.

These observations are not a universal removal list. qtizen does not apply them
at launcher startup, remove system packages automatically, or disable panel maintenance.
